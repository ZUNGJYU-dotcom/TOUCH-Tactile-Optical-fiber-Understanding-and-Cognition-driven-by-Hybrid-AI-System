# TOUCH Stable v0.19.7 至 v0.19.25 迭代报告

日期: 2026-09-03
比较对象: 上一版 Stable `v0.19.7` 与现存 Stable `v0.19.25`
适用范围: 普通 FBG + BaySpec 512 点光谱 + 九位置 P11-P33 + 光学 Fz 估计

## 1. 执行摘要

现存 Stable `v0.19.25` 不是对 `v0.19.7` 的小修补，而是一次完整的采集域、模型特征、在线状态机、记录链路和发布隔离升级。它将默认采集条件从旧版的 `5000 us` 切换为明确的 BaySpec `High Sensitivity` 模式和 `300 us` 曝光，并采用持久化 SDK 数据流；识别方法也从三日期混合采集数据上的通用模型，转为针对当前 300 us 高灵敏度采集域训练的九光栅联合指纹模型。

就当前普通 FBG 硬件和当前采集协议而言，`v0.19.25` 是更合理的生产版本。它在完整会话分组验证中取得 `96.78%` 接触准确率、`98.06%` 位置准确率和 `0.310 N` 光学力 MAE；精确运行时回放中，10,589 个专用空载帧没有触发误触，发生接触时输出的位置标签准确率为 `100%`，有意义接触的 P90 首次响应延迟为 `0 ms`，位置 P90 延迟为 `117.7 ms`。最后的真实设备验收还覆盖了按压、保持、松手和后续空载。

不过，这不等于已经证明新版在任意日期、任意光源或任意安装状态下都优于旧版。`v0.19.7` 的训练数据跨越三天，而 `v0.19.25` 的正式模型数据来自同一天；后者使用的 Blind1、Blind3 和 Blind4 已在揭晓答案后进入训练和模型选择，因此不能再作为独立盲测证据。当前最准确的结论是: `v0.19.25` 在当前 300 us 高灵敏度域内明显更稳定、更快、更轻量，但仍需一组新日期、未参与调参的独立数据验证跨日泛化。

## 4. 模型与数据迭代

### 4.1 v0.19.7 的模型边界

`v0.19.7` 使用 57,943 帧、250 个会话组和三个采集日期。其正式主线是 `literature_guided_three_date_v2`:

- 接触: Extra Trees，`response_raw136`；
- 位置: Extra Trees，`response_raw136`；
- 光学 Fz: SNV、Savitzky-Golay、OSC 处理后的 328 维特征配合 Ridge；
- 运行时输入仍然只有光谱，PX6D 只作训练监督和 Diagnostics 参考；
- Fz 训练范围约 `0-7.270 N`，输出没有固定上限裁剪。

该模型的长处是包含三个日期，能够直接暴露跨日期漂移问题。代价是不同曝光、灵敏度设置和采集条件被混合，训练分布与当前 `High Sensitivity / 300 us` 现场分布并不一致。

模型文件中还同时保留了旧 `tasks/task_metadata/all_feature_names` 结构和新的 literature-guided active payload。运行时会优先配置 active payload，但模型包在结构上并非严格的 current-only 模型。这也是旧模型文件达到 `227.09 MiB` 的主要原因之一。

### 4.2 v0.19.25 的模型边界

`v0.19.25` 使用 2026-09-02 同一采集域的 161 个完整会话、49,853 帧，全部遵循 `High Sensitivity / 300 us / 512 points`。数据来源为:

- `regular_v01916`；
- `regular_v01919`；
- 已清洗并揭晓答案的 `blind1`；
- 已清洗并揭晓答案的 `blind3`；
- 已清洗并揭晓答案的 `blind4`。

`blind2` 因数据异常被明确排除。Blind1、Blind3、Blind4 进入训练后已不再是独立盲测集。

新版对三个任务使用不同但相互一致的特征视图:

- 接触: 264 个基线相对完整光谱特征 + 75 个九光栅联合特征，共 339 维；
- 位置: 75 个九光栅联合特征；
- 光学 Fz: 264 + 75，共 339 维；
- 接触起始还计算 36 个九光栅局部响应量，覆盖每个候选光栅的波长、面积、峰高和形状变化；
- 常规起始至少要求 5 个通道出现低阈值响应、3 个通道出现标称响应；只有全谱接触与位置模型同时高度确信时，才允许更轻触的保守通道。

因此，新版满足当前项目反复确认的原则: 按压一个位置时，判断依据是九个光栅共同形成的光谱指纹，任何单一光栅都不足以单独证明接触或位置。

### 4.3 运行时模型隔离

新版模型包声明 `runtime_model_isolation.mode=current_only`，并绑定:

- runtime schema: `same_day_joint_nine_fbg_v4`；
- dataset ID: `ordinary_fbg_20260902_same_day_joint_fingerprint_v2`；
- legacy fallback: `false`；
- active task count: `3`；
- legacy task model count: `0`。

加载器会校验 schema、dataset ID 和 current-only 标志；如果模型重新出现 `tasks`、`task_metadata` 或旧 feature contract，运行时会直接拒绝加载，而不是静默回退。Stable 包内只有一个 `.joblib` 模型和一个哈希绑定的 deployment JSON。

## 5. 性能证据与正确解读

### 5.1 模型层指标

| 指标 | v0.19.7 主线模型 | v0.19.25 当前模型 |
| --- | ---: | ---: |
| 接触 accuracy | 0.8796 | 0.9678 |
| 接触 macro F1 | 0.8271 | 0.9629 |
| 位置 accuracy | 0.9066 | 0.9806 |
| 位置 macro F1 | 0.9026 | 0.9805 |
| 光学 Fz MAE | 0.631 N | 0.310 N |
| 光学 Fz R2 | 0.749 | 0.929 |
| 光学 Fz 标定斜率 | 0.873 | 0.883 |

这些数字显示新版在各自验证协议下更强，但不能把差值视为严格 A/B 提升，因为验证域不同:

- `v0.19.7` 的上述主线指标来自 leave-one-date-out、按会话分组的跨日期验证，难度更高；
- `v0.19.25` 的指标来自同日完整会话分组和完整采集批次留一验证，与当前部署域更一致；
- 新版尚未完成一个全新日期的冻结盲测，因此当前不能声称已经解决跨日泛化。

正确的表述应是: 新版显著提高了当前采集协议内的识别与力估计质量，同时牺牲了旧版已经具备的跨日期训练覆盖；下一阶段必须用新的独立日期数据验证这种域内提升能否保留。

### 5.2 精确运行时回放

`v0.19.25` 不是只看离线分类器分数，还把完整模型放入与软件一致的基线、接触、位置锁定和释放状态机中回放。现有结果为:

- 161 个会话，49,853 帧；
- 10,589 个专用空载帧，误触率 `0%`；
- 有效接触帧覆盖率 `99.85%`；
- 输出位置时的准确率 `100%`；
- 正式错误位置帧 `0`；
- 44 个位置帧因确认门控暂缓输出，而不是错分给其他点；
- 有意义接触 P90 首次响应延迟 `0 ms`；
- 位置 P90 首次正确输出延迟 `117.7 ms`；
- 完整采集批次留一压力测试位置准确率 `99.09%`，macro F1 `99.08%`。

这部分是部署兼容性证据，不是独立盲测。因为相关批次已参与训练或模型选择，不能把 `100%` 输出位置准确率写成未知样本的泛化准确率。

### 5.3 真实硬件验收

`v0.19.25` 晋级 Stable 前完成了一次真实设备按压与释放检查:

- 捕获 54 个按压/释放帧；
- 没有帧顺序倒退；
- 最终状态成功回到 no-contact；
- 随后监测 31 个空载帧，正式接触和视觉接触均为 0。

这证明当前修复确实进入冻结 EXE，并覆盖了最近现场出现的“松手后滞留”和并发请求导致状态倒退的问题。它仍不是九个位置、多轮、多日期的完整硬件验收。

## 6. 延迟与采集效率

本轮迭代同时处理了曝光时间、SDK 进程生命周期和 Record 阻塞三个不同的延迟来源。

1. 曝光从 `5000 us` 降至 `300 us`，且使用 High Sensitivity 保持短曝光下的光谱可读性。
2. SDK 改为持久流，只有流故障或传感模式/曝光设置改变时才重启 helper。
3. Record 先保存原始 512 点光谱和 PX6D，再读取严格同帧的模型缓存；没有同帧结果时明确标记 deferred，绝不复用旧预测。
4. Record 默认 10 ms 轮询，每 10 帧或 250 ms 持久写盘。
5. 本地 `512 点光谱 + 识别 + 力` 管线基准达到 `43.2 fps`，而此前同步推理路径约为 `3 fps`。

`43.2 fps` 是软件管线容量基准，不代表每次真实 BaySpec 会话都能达到同样物理帧率。训练记录中的中位帧间隔约 `100.8 ms`，对应约 `9.92 Hz`；设备、USB/SDK、并发请求、磁盘和采集会话行为仍会限制实际速率。

## 7. 在线稳定性修复

### 7.1 基线

旧版使用 5 帧当前会话中位数，并允许松手后自动更新运行时基线。新版改为 12 帧稳定中位数，并把模型基线固定在当前会话；静止恢复逻辑可以清空显示，但不能改写模型参考坐标。用户明确执行 Set Baseline 时，可以用已确认无接触的当前状态替换过期参考。

这项修改解决了两个相反问题:

- 自动重设基线时误把持续按压当作新空载，导致后续按压无响应；
- 长时间漂移或旧会话基线继续驱动模型，导致空载误触和位置偏移。

### 7.2 持续按压与位置跳变

新版在接触建立后保留当前位置。最初 2 s 允许起始瞬态收敛；此后只有位置置信度至少 `0.55`、margin 至少 `0.15`，并连续 8 帧支持新位置，才允许切换。这一逻辑直接针对近期观察到的 P11 跳 P13、P21 跳 P33、P23/P33 空载抢占以及持续按压不能保持等现象。

### 7.3 松手与乱序

最新版增加两层保护:

- 晚到的 SDK 帧不能倒退时间状态，也不能抹掉已经记录的接触峰值；
- 如果接触分类器在松手后仍饱和，则要求相对接触峰值至少恢复 60%、完整光谱安静、空间置信度低，并连续两帧跨越至少 180 ms，才清除接触。

持续按压没有恢复轨迹，因此不会仅因一时位置置信度下降而被错误释放。

## 8. Contact Map 与力的真实含义

当前 Contact Map 已由当前帧模型驱动，具体是经过接触门控的位置后验概率、EMA 稳定和光学 Fz 缩放后的九位置表面。Diagnostics 中的 observed map 则显示九个 FBG 的实际耦合光谱响应。

需要严格区分:

- Contact Map 是模型推断的当前接触位置分布，不是连续压力阵列直接测得的压力场；
- 光学 Fz 是用 PX6D Fz 监督训练后，由光谱单独推断的压缩力；
- PX6D 不参与运行时模型输入，只用于训练标定、录制参考和 Diagnostics；
- Fz 训练覆盖约 `0-6.983 N`，软件不设置固定上限，但高于该范围的结果属于外推，不能按已标定精度解释。

## 10. 最近迭代路线

从 `v0.19.7` 到 `v0.19.25` 的主要进展可归纳为五个阶段。

### 阶段一: 采集协议统一

`v0.19.12-v0.19.13` 将 High Sensitivity 和 300 us 写成显式合同，增加可调曝光范围，并建立持久化 SDK stream。软件不再依赖设备或 helper 的隐式默认值。

### 阶段二: 空载、低力和高帧率采集修复

`v0.19.14-v0.19.16` 引入可信空载、低力快速起始、固定模型基线和非阻塞 Record。重点从“模型离线分数”转向“实际界面是否误触、是否漏掉轻触、记录是否同帧”。

### 阶段三: 当前采集域重训与九光栅判定

`v0.19.17-v0.19.20` 使用新采集数据重训，取消单光栅证据，要求完整九光栅联动。该阶段主要解决 P23/P33 误触、P11/P21 持续按压丢失和位置错分。

### 阶段四: 盲测、位置锁和记录可追溯性

`v0.19.22-v0.19.24` 先对未揭晓数据冻结结果，再在揭晓后清洗标签并决定是否纳入训练。Record 同步保存界面实际显示的接触、位置、置信度、margin 和光学力，同时保留 formal/raw 字段，便于比较在线决策与离线重建。

### 阶段五: 真实释放修复与 Stable 晋级

`v0.19.25` 针对真实硬件暴露出的乱序帧和松手滞留，增加帧顺序保护及九光栅恢复释放。用户现场确认按压、保持与释放基本正常后，Beta 原样晋级 Stable，并为 Stable 单独复制经过验证的配置和用户设置。

## 11. 当前判断

### 适合继续使用 v0.19.25 的原因

- 它与当前 BaySpec High Sensitivity / 300 us 采集域一致；
- 接触、位置和 Fz 都使用完整光谱或九光栅联合指纹；
- 已解决近期最影响使用的误触、位置跳变、持续按压丢失、松手滞留和乱序帧问题；
- Record 可保存原始数据、PX6D 参考和同帧在线预测，便于继续训练与审计；
- Stable 与 Beta 设置隔离，且运行时只有一个哈希绑定模型；
- 包体和模型显著缩小，冻结自检和完整测试均通过。

### 仍不能宣称已经解决的问题

- 没有全新日期、完全封存答案的独立外部验证；
- 更换光源、重新插拔光路、改变安装预应力后，基线相对特征可以缓解整体光强差异，但不能保证模型自动跨域有效；
- 高于约 6.98 N 的光学力虽然不会被 UI 截断，但属于未标定外推；
- 当前只验证单点 P11-P33，尚不能把 Contact Map 解释为非光栅区域的高分辨率连续压力场；
- 当前 Stable 仍是普通 FBG 版本，不能把这些结果直接当作 mFBG 强度解调 3x3 的性能证据。

## 12. 下一轮验证建议

下一轮最有价值的工作不是继续在同日数据上追求更高回放分数，而是冻结 `v0.19.25` 后采集一个新日期的独立测试集。采集时保持 High Sensitivity、300 us、512 点和同样的机械安装，答案文件在推理结果冻结前不可读取。

新日期验收至少应同时报告:

- 专用空载帧误触率和误触 episode 数；
- 每个位置的接触 episode 检出率；
- 九位置混淆矩阵，重点观察 P11/P13、P21/P33 和 P23/P33；
- 持续按压覆盖率、松手残留时间和二次按压恢复；
- 接触与位置 P50/P90/P95 延迟；
- 光学 Fz 的 MAE、R2、斜率、迟滞和分位置误差；
- 光源重启、软件重启和重新 Set Baseline 前后的稳定性。

若新日期结果保持当前水平，才能把“同日域内稳定”升级为“跨日期可复现”。如果下降，应优先引入日期/设备域归一化和显式漂移质量门控，而不是把新日期数据直接混入训练后再次用同一批数据自证。

## 13. 结论

`v0.19.25` 应继续作为当前 Stable。与 `v0.19.7` 相比，它的核心价值不是单个准确率数字，而是让采集条件、九光栅物理证据、模型特征、在线状态机、同帧记录和冻结发布形成了一个一致且可审计的闭环。它在当前硬件域内已经表现出更低误触、更稳定的位置、更可靠的松手和更低的软件延迟，同时将运行时模型缩小约 95.8%。

现阶段最需要守住的边界是: 新版优势已被同日分组验证、运行时回放和一次真实硬件按压/释放支持，但尚未被新日期独立盲测支持。后续工作应以跨日复现为首要门槛，并继续保持普通 FBG Stable 与 mFBG 科研 Beta 的数据、模型、端口、配置和发布目录隔离。
